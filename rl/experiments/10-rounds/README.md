# Harmonies：正式 10 轮 RL 实验版本

这里集中管理**实际完成 10 轮 self-play → 训练 → 晋级测试**的实验。版本号表示完整实验方案，不表示网络 schema，也不是游戏内启发式 AI 的 v1/v2/v3。最后整理日期：2026-10-29。

目前共 **2 个已完成版本**。每版的原始轨迹、replay、全部 checkpoint、日志、看板和核验文件均实际存放在该版的 `run/` 中。

| --- | --- | --- | --- | --- |
| [v001-fixed32](v001-fixed32/README.md) | 全状态 32 模拟、每轮 1000 局、固定训练 400k 行 | 10/10，已核验 | [打开](v001-fixed32/run/dashboard.html) | [manifest](v001-fixed32/manifest.json) |
| [v002-playout-cap](v002-playout-cap/README.md) | 2000 局、25% expensive64 / 75% cheap16，仅 expensive 训练，预算上限 2W | 10/10，已核验 | [打开](v002-playout-cap/run/dashboard.html) | [manifest](v002-playout-cap/manifest.json) |

## 方案对比

| 配置 | v001-fixed32 | v002-playout-cap |
| --- | --- | --- |
| 每轮 self-play 局数 | 1000 | 2000 |
| 每个原子决策新增 MCTS 模拟 | 全部 32 | 独立抽样：25% 为 64，75% 为 16 |
| Root Dirichlet noise 权重 | 全部 0.25 | expensive 为 0.25，cheap 为 0 |
| 选招温度 / 回合内树复用 | 1 / 开启 | 1 / 开启 |
| Replay 收录 | 全部决策状态 | 仅 expensive 状态 |
| 每轮训练行数 | 固定 400000 | min(400000, 2 × 实际窗口行数) |
| 窗口采样 | 每遍无放回；不足预算则开始下一遍 | 每遍无放回；每轮每行最多两次 |
| Gatekeeper | 100 局；serving 128 模拟；50% 晋级 | 相同 |

共同配置：A 面、两人、无自然之灵；数值特征 1614 维，5 个市场卡牌 ID 使用共享 8 维 embedding；共享 FFN `1654 → 128 → 128`，policy 和三个 value head；总参数 343555。玩家持牌为固定 32 卡位 × 3 特征。AdamW、学习率 0.001、batch size 64；window 参数 `min_rows=100000`、`taper_scale=50000`、`expand_window_per_row=0.4`、`taper_window_exponent=0.65`。

两版均以 seed 1729 随机初始化，初始权重 SHA256 完全相同，各自拥有独立 replay；v002 并非从 v001 checkpoint 续训。每轮由 best 收集数据，从 latest 续训，即使上一轮未晋级也继续训练 latest。晋级对局关闭噪声、温度 0、每动作新增 128 模拟，平局半胜，测试数据不进入 replay。

| --- | ---: | ---: |
| 训练 self-play 总局数 | 10000 | 20000 |
| Replay 样本数 | 953730 | 487277 |
| 累计训练消费行数 | 4000000 | 2799410 |
| 优化器更新次数 | 62500 | 43746 |
| 晋级测试总局数 | 1000 | 1000 |
| 晋级轮次 | 1–10 | 1、2、3、5、6、7、8、10 |
| 最终 best / latest | 第 10 轮 / 第 10 轮 | 第 10 轮 / 第 10 轮 |

| 末轮 self-play：分数 / 入住动物 / 完整牌 | 35.886 / 2.313 / 0.1195 | 40.046 / 2.49275 / 0.16375 |
| 末轮晋级双方：分数 / 入住动物 / 完整牌 | 48.645 / 3.34 / 0.285 | 51.235 / 3.72 / 0.34 |

以上终局指标均为每局双方各计一次的均值。self-play 是本轮训练前 best 的表现，晋级统计混合本轮候选与此前 best，不能视为最终模型单独的能力。两版采样策略、训练量与晋级对手不同，尚无统一基准的独立对战结果；不能仅凭这些均分断言 v002 棋力更强。

后续版本的主要对比指标采用：**第 10 轮结束时 best 对固定基准的独立测试得分率 `(胜 + 0.5 × 平) / 总局数`**。固定基准为 v002 的第 10 轮模型，默认统一 serving 每原子动作新增 128 模拟、噪声 0、温度 0，至少 400 局按 seed 交换先后手；种子独立于训练与晋级，报告按配对 seed 计算的置信区间。模型扩容对比另注明此预算不等于相同推理耗时。当前该项均标记为“未执行”，不得用晋级胜率代替。

## 目录与文件

```text
rl/experiments/10-rounds/
  README.md                      总索引、配置与结果对比、版本规则
  v001-fixed32/
    README.md                    本版目的、配置、结果、入口
    manifest.json                结构化登记：配置、逐轮结果、模型哈希
    artifacts.sha256             run 内全部文件的 SHA256 清单
    relocation.json              此次目录迁移核验
    run/                         完整原始实验产物（本地大文件）
  v002-playout-cap/
    ...
```

README、manifest、哈希清单和迁移核验进入 Git 管理；`run/` 沿用原实验大文件不进 Git 的策略。克隆仓库能获取实验记录，完整对局、数据库与 checkpoint 需要另行备份/传输，不能把 Git 当作这些产物的备份。

旧路径 `rl/runs/selfplay-10rounds-20261015`、`rl/runs/playout-cap-10rounds-20261018` 保留为指向新 `run/` 的相对符号链接。它们不是第二份实验。历史日志与 JSON 中的旧绝对路径保留原样，避免改变原始记录。核验脚本仅做必要的路径调整，原脚本保存在各 run 的 `_relocation-originals/`；每个未修改原文件都经搬迁前后完整 SHA256 核对。

可在任意版本的 `run/` 下执行 `shasum -a 256 -c ../artifacts.sha256` 检查登记时产物完整性。核验脚本会更新自身输出，重新执行后需审阅变化再更新清单；不要把生成时间变化误判为训练数据损坏。

## 后续版本规则

1. 使用下一个连续编号，如 `v003-<简短方案名>`，每个版本有自己的 `run/`。正在运行的版本明确标记状态，只有 state 为 complete、10 轮 metrics 齐全且核验通过，才计入“已完成版本”。
2. 启动前记录相对前版的改动、代码 commit（如有未提交改动，保存 patch）、完整配置、初始化模型与哈希。运行中的当前 HEAD 不能冒充历史实验的代码版本。现有两版没有独立 launch commit 证据，因此 manifest 不猜测填充。
3. 完成后补齐本版 README、manifest、逐轮窗口/消费量/晋级记录、best/latest 与哈希、完整性清单、看板及核验入口，并更新本索引。
4. 已登记的 10 轮结果固定保存；继续到更多轮、修改配置或重新训练，应建立新实验目录并明确父版本、checkpoint 和 replay 来源，不能覆盖现有结果。
5. 小规模 smoke、拟合审计、value 准确率与条件方差实验放在诊断目录，通过版本文档关联；不占正式训练版本号。网络扩容目前仅讨论，尚无 v003 训练结果。
