# MCTS 最后一回合验证

2026-10-10 完成 100 局随机自对弈，得到双方各一个最后回合起点，共 200 个局面。每个局面均生成 HTML 报告，含双方版图、动物牌及栖息地图案、市场、供应，以及 128 / 1024 次 MCTS 和穷举的方案对照；方案支持逐步回放。

本地报告入口：[全部 200 个局面](../rl/runs/mcts-audit-20261010/index.html)。原始对局及输入在同目录 `inputs.json`，逐局搜索结果在 `game-NNN-seat-N.json`，汇总在 `summary.json`，复核记录在 `verification.json`。生成产物位于被 Git 忽略的 `rl/runs/`；以下命令可重建。

```bash
npm run rl:audit-mcts -- --games 100 --seed 71000 --workers 4 \
  --output rl/runs/mcts-audit-20261010
```

## 实验定义

- A 面、两人、无自然之灵，种子 71000–71099，交替先手。随机策略在**合法原子动作**中均匀抽样，不是均匀抽样完整回合。
- 对局完成后，取双方最后一次实际回合开始前的状态。保留原始观察，再把测试输入的 `finalRound` 设为当前 `round`，对应编码中的“最后一回合 = true”。不修改版图、持牌或供应。
- 不加载 NN。合法动作 logits 全为 0，即均匀 policy；value 为双方当前绝对得分 `/100`。搜索配置 `rankWeight=0`、`relativeWeight=0`、`absoluteWeight=1`，无根噪声，temperature 为 0，其余 PUCT / FPU 参数沿用默认值。
- **128 / 1024 是每个局面整棵树的模拟次数，不是每个原子决策的预算。** 同一局面使用相同搜索种子；1024 次包括前 128 次的探索过程。沿用现有跨玩家搜索，首位玩家结束回合后会继续模拟对手；此时己方绝对得分已固定。
- 在生产 `search` 中增加可选的只读 `onTurnEnd` 观察回调，记录搜索实际走到的当前玩家完整回合。没有额外 rollout、补齐动作、重新搜索，也没有修改 PUCT、展开、回传或动作选择。
- Top 3 按己方回合末实际得分排序，以“己方最终版图及持牌”去重；同一终点的不同操作顺序不占多个名额。分数相同按固定终点键排序，不按动物数量破同分。**这与生产 serving 根据访问权重推荐下一原子动作是不同指标**；报告另外展示实际根动作及根边统计。
- 搜索不足 3 个完整终点时按实际数量展示；零方案表示树尚未走到 `endTurn`，不表示规则上无合法回合。
- 穷举遍历 `legalActions` 的所有分支，遇 `endTurn` 记录并停止当前回合，限时 60 秒。只合并完全相同的回合内规则状态，包括版图、持牌、市场、供应、待放地形及拿牌／拿片标记；忽略不影响规则的持牌顺序和待放片顺序。无启发式剪枝。穷举完成才标记“已证最优”。

## 结果

| 指标（共 200 个局面） | MCTS 128 | MCTS 1024 | 穷举 |
|---|---:|---:|---:|
| 没有完整方案 | 149 | 15 | 0 |
| 不足 3 个完整方案 | 190 | 26 | 0 |
| 找到全局最优分 | 8 | 39 | 200 |
| 有方案时，最好方案与最优分的平均差距 | 6.76 分 | 5.30 分 | 0 分 |
| 平均单局面耗时 | 62.5 ms | 416.8 ms | 634.1 ms |

200 个局面全部在 60 秒内完成穷举，最长 **3.620 秒**。测试环境为 Apple M4、Node v24.17.0，4 个进程并行处理不同局面；以上为该并行配置下的墙钟时间，包含诊断统计开销，不是独占 CPU 的纯 MCTS 基准。

这次实验暴露了当前原子动作树在小预算下的完整回合覆盖问题：每次模拟只展开一个新节点，当前分叶估值也不能预见尚未完成的布局收益。因此，整棵树 128 次模拟通常不足以产生整回合 Top 3。结果不能直接作为训练后 NN 的棋力结论，也不能等同于逐动作重新搜索的 serving 表现。当前保留算法原样，方便后续在同一批固定局面上比较改动。

## 正确性复核

- 重放 100 局原始对弈的全部 8,904 个动作，确认 200 个输入确实是双方最后回合的起点，并检查最后一回合编码标记。
- 所有展示的 1,225 个完整方案逐步检查合法动作、回合边界、动作标签、最终版图及得分。
- 使用测试目录中冻结的独立计分实现，复核上述方案和 200 个初始状态，共 1,425 次，全部一致。
- 检查全部局面的 1024 次搜索最好已发现分数不低于 128 次，以及所有 MCTS 方案分数不超过穷举最优分。
- 单元测试验证开启观察回调前后 MCTS 输出完全一致、只记录当前玩家的完整回合；小局面的去重穷举与不合并状态的直接遍历结果一致；超时明确标记未完成。
- 第一局双方局面另用不合并任何状态的直接 DFS 交叉验证，分别遍历 37,721 / 24,374 条边，得到 2,053 / 1,925 个不同终点，与去重穷举的终点数量及 Top 3 完全一致。
- 本地 Chrome 检查报告无脚本错误、逐步回放和索引筛选有效，桌面与手机宽度无水平溢出。
- 全量 71 项测试、生产构建和 RL TypeScript 类型检查全部通过。

这些检查没有发现非法方案、计分差异或观察回调引起的搜索行为变化；它们验证本次实验和相关代码路径，不是对整个 MCTS 实现的形式化证明。
