# 当前回合启发式 AI（v3.1）

默认 AI 只优化自己的当前完整回合，不模拟对手或后续自身回合。便宜评分保留 v1 公式；完整估值在 v1 六项目基础上保证新增未入住牌不降低估值，并复用规则分、项目和局面缓存；不使用 RL、远程模型。搜索在 Web Worker 中运行，支持 1–4 人、Solo、自然之灵及暂停/继续。

## 参数与目标

- 默认每回合 3500 ms 软预算，设置页可选 1000 / 3500 / 10000 ms。
- 初始束宽默认为 6，程序参数支持 1–32；完整搜索一轮后翻倍至 12、24……。
- 每类日志 top-k 默认为 3，可选 1 / 3 / 5。它只影响输出数量。
- 固定随机种子默认 1729。旧存档的 depth 字段保留可读，但此搜索器实际深度固定为 1，设置页不再提供多回合深度。
- 从搜索已经完成并评分的回合中，最大化回合结束后的完整 V。评分完全相同时，依次比较实际剩余空牌位（多优先）、实际规则总分、动作序列字典序。空牌位按被评估玩家的 4 减未完成卡牌数计算；已完成的动物牌/自然之灵不占牌位，未完成自然之灵占牌位。该顺序统一用于完整方案、束搜索、贪心保底及日志 top-k。

束搜索不保证全局最优。3500 ms 包含保底、搜索及日志整理，是软预算：完整保底与已经开始的一次评分允许完成。动作逐步展示的 240 ms 间隔不计入思考时间。

## 基础评分与拿牌收益下限

中间局面的便宜评分：

```
S = 当前规则总分 + sum_每张未完成牌(max_补建入住项目(G_animal * q))
```

每张牌只估算下一次入住。普通动物 G 是下一档增分；自然之灵 G 为当前版图上的该灵计分。补建的地形收益不计入 S。各张牌独立估算，不扣减其他牌的虚拟资源或落点，允许乐观近似。

完整回合先使用 v1 六项目贪心估值，再执行下面的单调性修正：

```
V_greedy = 当前规则总分 + 最多六个顺序项目的 sum(G * q)
m = sum(m_c)
F = max(0, B - sum(H))
d_c = max(0, m_c - H_c)
p_c = A_c / sum(A)                     # 池为空时为 0
q = exp(-m/max(1,B) - 0.5*sum(d_c²/(1+F*p_c)))
```

项目包括已持有动物的一次补建入住和一枚合法地形放置。V 的 G 包括地形、动物、自然之灵净收益；仅选正收益项目，按 W=G*q 降序、m 升序、项目键升序决定。每选一个项目就在虚拟版图执行、扣减 B/H/A，再选择下一项目。落点不能重复占用，共享地形只付新增成本。m>B、sum(d)>F 或 d_c>A_c 时不可选。

当前玩家未取片时，完整 V 分别以每个完整供应组作为 H，取最优值；S 则沿用 v1 的 pending。所有计算都只使用公开状态。回合末补充资源来自同一个公开信息抽样，种子为 seed + rootRound*1009 + rootPlayerId。

本版保留 v1 的期限公式和项目并列坐标顺序。没有同时引入 v2 的结束轮次修正或版图旋转规范化。因此已知的 v1 跨回合预算变化及旋转并列偏好仍存在；v3.1 只修正拿牌单调性与同分排序。`createEvaluator("v1")` 与冻结参考公式逐局面验证；v2 估值入口仍保留，供历史测试。

### 新拿牌不能降低估值

令 U 为当前持有、placed=0 的普通动物牌集合，其他牌为 K（含已经入住的动物牌和全部自然之灵）。定义：

```
V(K ∪ U) = max_{S ⊆ U} V_greedy(K ∪ S)
```

评估所有普通未入住牌的启用子集，包含全用和全不用。新增一张 placed=0 的动物牌会保留之前的全部子集，因此在版图、预算及资源池等其他输入相同时，V 不会下降。S 本来就是每牌非负项之和，拿新牌也不会降低 S。这里不计空牌位的未来价值；空牌位只用于同分排序。

合法局面 U 最多 4 张，最多比较 16 个组合。先评估全用，再按原持牌顺序构造位掩码，从大到小评估其他子集。只在数值严格更高时替换当前最佳；不以四舍五入后的近似值选择最大值。保留此前期限公式与每个贪心项目的并列规则。

禁用某张牌只是不让它参与虚拟项目；没有实际弃牌，也没有释放真实牌位。恢复原始 actualScore/cardScores，记录获胜子集的真实可行项目链；不通过单纯抬高 value 伪造项目收益。ignoredCards 记录禁用牌，greedyValue 记录未修正的全用估值。

复用子集估值缓存。只有所有子集比较完成才发布完整 V；超时保留此前已完成方案，部分最大值不写入修正估值缓存。每个未命中的六项目计算计入 fullEvaluations，包括用于下限的子集；所以 fullEvaluations 可多于 completePlans。日志仍只读取搜索期间已有的结果。

## 搜索步骤

1. 按 S 贪心完成一个合法当前回合，并对末局面计算一次 V，得到保底。没有根局面 V 的额外计算。
2. 从根局面运行宽度 w 的束搜索。每层先生成所有父节点的合法子节点，按完整局面键合并相同状态；相同状态保留字典序最小的路径，再评分。
3. 未完成节点按 S、实际空牌位、实际分、动作序列排序，保留前 w。没有按父节点独立截断，也没有强制保留操作类型。
4. 完成回合的节点计算 V 后立即加入候选集合，立即更新全程最佳方案。终点不占用中间节点的束宽。
5. 完成本轮后记录束宽；若曾剪枝，则 w 翻倍重搜，复用全部状态、转移、S、V 与评分内部缓存。未剪枝则已穷尽，结束搜索。
6. 时间或评分预算到达时，返回所有已完成方案中 V 最佳的一个，包括尚未完成的宽度轮次里已经完成的方案。中间路径不得返回。

相同地形片颜色仅枚举一个待放索引；合法入住的旋转由规则层合并。搜索键包含版图、动物、卡牌、供应、手中地形、操作权限、轮次等，不包含操作历史。A→B 与 B→A 只有最终完整状态一致才合并；不假定堆叠、入住锁格和拿牌顺序可以随意互换。每层去重发生在评分前，跨层/跨束宽再通过状态和评分缓存复用。

每次请求独立持有缓存。规则分缓存最多 8192 项，项目菜单最多 512 项；评分缓存键包含实际影响公式的版图、卡牌、期限、手中资源和颜色池等语义输入。地图旋转不参与当前去重；单个贪心评分保留 v1 的精确结果。

## 日志是搜索结果的转储

JSON 格式版本 3，算法版本 `current-turn-v3.1-monotone`。旧 v1/v2/v3 日志保持原数值和口径，依然支持导入存档、展示和混合导出。

- 中间动作显示 S，结束回合及完整方案显示 V/Q，明确区分；候选与完整方案记录实际 freeCardSlots。
- 每种操作只对已实际评分的候选取 top-k（结束回合按 V，其他按 S）；记录 legalCounts 与 evaluatedCounts，后者可能小于前者。选中操作独立保存。
- m、d、p、B、F、H、A、G、q、W 在实际评分时保存，日志不重新枚举项目。
- 前后都已有同口径评分才显示差值。根局面 S 和 V 没有参与搜索时不计算，before、gain、rootValue 留空，界面显示 — 或省略。
- 首条操作的 planSummary 保存前 k 个完整方案、完整 V 分解、完成及尝试束宽、合并重复数、S/V 计算次数、完整方案数、搜索/日志耗时。
- logEvaluations 必须为 0。日志整理只读已有评分、筛选和序列化，不调用评分器，也不应用游戏动作。
- 单个请求总耗时仍包含日志整理。程序审计支持 log=false；固定计算预算下，关日志或改 top-k 不改变动作、评分次数与搜索覆盖。

实际执行后的规则分 actualScoreAfter 由主界面正常计分记录；它与预测补充后的值分开显示。日志保存在 IndexedDB，常规局面保存在 localStorage，导出包含双方策略日志。
