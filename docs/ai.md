# 启发式 AI v1

本版没有 RL、训练模型或远程 API。人类与 AI 共用 `Action` 和规则引擎。AI 的估值和搜索在 Web Worker 中执行，操作结果逐步通过 `dispatch` 写回真实对局。

## 使用

设置页中，将任意玩家类型设为“启发式 AI”。支持 1–4 人任意组合，包括 AI Solo 和全 AI 观战。每位 AI 的配置独立保存：

| 参数 | UI 选项 | 默认值 |
| --- | --- | --- |
| 搜索深度 | 1、2、3 个自身完整回合 | 2 |
| 思考预算 | 1、3.5、10 秒 | 3.5 秒 |
| 日志 top-k | 1、3、5 个 / 操作类型 | 3 |

深度包含当前剩余回合。时间有限时，实际完成深度可能低于目标，界面及日志会明确显示。深度 0 表示使用完整合法的贪心保底回合。搜索预算为软预算：总计约 65% 留给搜索，其余用于决策诊断；构造合法保底回合和每种操作至少一个诊断候选会执行完毕，因此设备较慢或局面复杂时可能超出预算。每步展示间隔 240 ms 不计入思考耗时。

AI 回合可以暂停/继续。离开游戏或暂停会终止正在运行的 Worker；查看日志或规则也会暂停 AI，避免阅读时局面继续变化。AI 回合的人工落子和撤销按钮禁用；人类自己的逐步撤销、整回合重置仍然有效。

## 估值规格：local-projects-v1

`V = scorePlayer(current).total + potential`。每个候选动作的局部价值为 `ΔV = V(after) - V(before)`，完整回合搜索最终按叶子局面的 V 排序。

候选项目只有两种：

1. **一次动物或自然之灵入住**：枚举所有起点、六个旋转和合法建筑底层。当前堆叠必须是目标从底到顶的前缀，每枚追加地形通过 `canPlace`。入住格必须没有动物；已有动物的辅助格只能原样使用。只对已持有的未完成卡牌生成候选。
2. **一枚地形放置**：枚举每格和六种颜色，通过 `canPlace` 后保留。

项目的 `G` 是应用补建和入住后，调用同一 `scorePlayer` 得到的总分净变化。只保留 `G > 0` 的项目。因此会包含地形损失、卡牌档位增量和自然之灵变化。独立的多步零收益地形铺垫留给外层搜索；动物项目本身可以包含多枚地形。

估计剩余轮数：

```
bagRounds = 1 + floor(bagCount / (solo ? 9 : 3 * playerCount))
boardRounds = max(1, min_i ceil(max(0, emptyCells_i - 2) / 2))
R = min(bagRounds, boardRounds)
```

已标记最后一轮、袋空、当前玩家空格不超过 2 时 R=1。游戏结束时 R=0。根据行动顺序，将 R 换算为每名玩家剩余放置预算 B：当前玩家使用待放数量加上 `3*(R-1)`；本轮尚未行动的其他玩家使用 `3*R`；已行动玩家使用 `3*(R-1)`。没有剩余行动机会时不计潜力。当前玩家尚未取地形时，分别将每个完整供应组作为 H 进行估值，取 V 最大的一组；同分取供应组索引较小者。

颜色向量统一按 **水、灰、棕、绿、黄、红** 排列，索引 0..5 对应引擎颜色 1..6。

```
m[c] = 项目所需追加颜色 c 的数量
m = sum(m[c])
H[c] = 手中尚未分配的颜色 c 数量
A[c] = 未来颜色池，来自公开初始配比减去已使用和弃置资源
B = 剩余放置预算
F = max(0, B - sum(H))
d[c] = max(0, m[c] - H[c])
p[c] = sum(A) > 0 ? A[c] / sum(A) : 0
q = exp(-m / max(1,B) - 0.5 * sum(d[c]^2 / (1 + F*p[c])))
W = G*q
```

若 `m>B`、`sum(d)>F` 或任意 `d[c]>A[c]`，项目不可选。

在临时版图上至多选择 6 个项目。每次重新生成全部候选，选择 W 最大者，应用项目并扣除预算。优先使用 H，不足部分扣除 A。更新后的版图自然消除落点冲突，已经补齐的辅助地形也不会再次付费。辅助格后续仍能合法加高；只有真实入住格被锁定。

并列顺序：W 四舍五入到六位小数后降序；m 升序；动物先于地形；卡牌 ID、起点格索引、旋转编号和追加颜色序列按数值字典序升序。可重建目标堆叠的建筑底层按灰、棕、红枚举。无额外空间或联动加分。

估值是有限局部项目的启发式折算，不是经过校准的终局预测。每回合固定占两格的假设、把未来供应看作颜色池、六步贪心均为明确的近似。

## 搜索与信息边界

`observe` 只复制公开状态、观察者自己的自然之灵候选、袋子/牌库数量，以及从公开信息推算的未知资源集合。真实袋子与牌库的排列不会传入 Worker。其他玩家未选的自然之灵仅保留“尚需选择”这一状态。

`sampleGame` 用固定种子生成假想袋子和牌库。自然之灵尚未选择的其他玩家也使用假想候选。默认 seed=1729；当前局面使用 `seed + round*1009 + playerId`，第二种后续场景再加 7919。

先构造一个完整合法的保底回合，再做束搜索（默认宽度 6，可通过程序配置 1–32）。回合内部按合法原子动作展开，支持拿牌、入住与地形放置交错。相同颜色的待放片只枚举第一个索引；等价局面合并。每次展开保留便宜排序的全局前 beamWidth 个候选和每个操作类型的第一名，下一层合并后再保留 beamWidth 个节点。完整回合用上述六项目估值重新排序。

便宜排序仅用于剪枝：当前规则分，加上每张未完成卡牌最佳一次入住的折算动物增量；不运行六步补建，也不把这项近似分冒充日志中的完整 V。自然之灵的便宜增量使用当前版图的 spiritScore。并列时当前实际分较高者优先，再比较动作序列的数值键。操作类型顺序为选择自然之灵、拿牌、拿地形、放地形、入住、结束回合。

深度 2/3 在两个抽样未来中模拟对手的贪心回合，再搜索根玩家的下一/下两回合。未来自身回合的束宽上限为 2。候选完整通过两个场景后取均值；整层完成才替换上一深度的结果。超时保留已发现的最佳完整合法回合，绝不提交半个计划。

这是带剪枝和对手近似的搜索，不保证全局最优，也不保证每次加深都更强。日志同时保留当前动作的局部 ΔV 与最终完整回合搜索值，它们可能不一致。

## 日志与导出

游戏顶部“操作记录”打开完整日志，点击 **导出游戏日志** 下载 JSON。有人类参与时包含普通操作记录和结构化动作；有 AI 参与时额外包含已经执行的决策诊断。

每个 AI 决策包含：

- 公开的操作前局面、玩家、轮数、对应普通日志索引、AI 配置。
- 操作前完整估值、实际选中动作及其完整估值和 ΔV。
- 每种操作的 top-k 候选，各自的完整估值、最多六个局部项目、G/m/mByColor/d/p/H/A/B/F/q/W。
- 每种操作的合法候选数与完整估值数、目标与完成深度、完整回合搜索值、节点数、整回合思考时间及超时/保底标记。

**top-k 的范围是经过剪枝后完整估值的候选，不是全部合法动作或整个搜索树。** 先按便宜排序选该类型前 k 个进行完整估值；受预算影响可少于 k 个，但每类至少评估一个。实际执行的动作始终另存，即使未进入某类 top-k。界面和导出文件均说明覆盖范围。未执行、被取消的计划不写入游戏日志。

当前对局及普通动作仍存入 localStorage 的 `harmonies.session.v1`。体积较大的 AI 日志存入 IndexedDB `harmonies-logs` / `sessions`，以会话 UUID 关联。刷新后加载日志再允许继续游戏。新游戏使用新 UUID；旧存档自动分配 UUID，未配置 AI 的玩家仍为人类。存储失败时页面会提示，并可在关闭页面前导出内存中的日志。

## 验证

```
npm test
npm run test:e2e
npm run build
npm run benchmark:ai
```

基准运行固定的 Solo A、Solo B+自然之灵、双人 A+自然之灵、四人 B，对比随机合法策略、单步实际分贪心和本版 AI。检查地形/卡牌守恒、合法动作、最终结束和等回合数。输出位于 `/tmp/harmonies-ai-benchmark.json`。`AI_BENCH_MS` 可覆盖预算，例如 `AI_BENCH_MS=1000 npm run benchmark:ai`。限时搜索的节点数受设备负载影响；测试可注入固定节点预算和时钟，以验证确定性。
