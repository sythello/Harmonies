# v3 当前回合搜索与原始 v1 对照

本轮实现与确定性规则见 [ai.md](ai.md)。原始 v1 取自 Git 提交 `f36c7ccada107220867722f460c67da02215c91b`，通过 `git archive` 提取完整未修改的代码到临时目录；本轮不使用计数插桩后的 v1。

## 实验设置

- 两方相同每回合软预算：3500 ms；初始束宽 6、top-k 3、AI seed 1729。
- v1 保留原始深度 2 和 65% 搜索 / 35% 日志预算；v3 固定当前回合、逐次扩大束宽、日志零额外估值。使用不同搜索结构正是实验变量。
- 保持 v1 的 S/V 与期限公式，不同时引入 v2 的期限修正或旋转规范化；原 v1 的已知估值近似也随之保留。
- A 无自然之灵 seed 11、B 无自然之灵 seed 13、A 有自然之灵 seed 17、B 有自然之灵 seed 19。每组双人对局交换先后手，并让两版分别运行同一种子的 Solo，共 16 局。
- 正式对局严格串行。每场先各用 100 ms 配置预热一次，丢弃预热方案。实际游戏由同一规则引擎执行，逐动作验证合法性和资源守恒，逐回合用原始/当前计分器逐字段核对。
- 所有 AI 只接收公开观察。对局胜负按最终规则分和动物方块的官方同分规则决定；不把 S 或 V 的大小当作棋力结果。
- 用外部墙钟记录整个规划调用，包含保底、搜索、日志准备；另记 CPU 时间和内部耗时。相同软预算不表示逐回合消耗了严格相同的 CPU 时间，必须同时报告实际耗时和超限。
- 本轮使用与此前 v2 对照相同的四组预设种子，便于比较；这是小样本回归，不是独立留出的强度评估集。中途没有根据胜负调参。

运行命令：

```sh
AI_COMPARE_OUTPUT=docs/ai-v3-time-comparison.json npm run benchmark:compare-ai
```

原始数据：[ai-v3-time-comparison.json](ai-v3-time-comparison.json)，包括版本摘要、环境、每回合动作、评分分解、完整搜索统计和耗时。旧 v2 对照保留在 [ai-time-comparison.md](ai-time-comparison.md)。

## 验证

- 52 项单元测试通过，其中包括 v1 S/V 及项目明细的逐局面等价检查、评分前去重、固定预算下日志开关和 top-k 不影响搜索、超时保留截至当时最佳完整方案、最后回合独立穷举最优分 89。
- 11 项浏览器测试通过，覆盖暂停/交接、Solo 结束、日志导出、旧存档兼容、IndexedDB 恢复及移动端布局。
- 生产构建、比较脚本严格 TypeScript 检查、diff 空白检查通过。
- 100 ms 冒烟对局只用于执行正确性，不作为强度结果。正式比较前修正了终点多算 S 的问题并重新验证，之前中断的预跑不纳入下面结果。

## 实测结果

正式运行于 2026-10-02（America/Los_Angeles），UTC 2026-10-02T07:00:19.571Z 至 2026-10-02T07:12:04.311Z，约 11 分 45 秒。16 局共 256 个行动回合，全部正常结束；合法动作、各色资源和牌守恒、计分等价及多人等回合数检查均通过。测试结束后重新核对源码 SHA-256，与运行开始时相同。

**双人 4 胜 4 负，平均分差 −0.875；Solo 四组平均领先 4.25 分。** 这些结果没有证明 v3 稳定强于 v1。

### 耗时与覆盖

| 指标 | v1 | v3 |
| --- | ---: | ---: |
| 玩家行动回合数 | 127 | 129 |
| 平均墙钟耗时 | 2447 ms | 2977 ms |
| 墙钟 P95 | 3824 ms | 3511 ms |
| 墙钟最大值 | 4709 ms | 3535 ms |
| 平均进程 CPU 时间 | 2764 ms | 4082 ms |
| 超预算 100 ms 以上 | 16 | 0 |
| 仅贪心保底 | 2/127 | 1/129 |
| 完整方案数中位数 | 未采集 | 185 |
| 日志整理平均 / P95 | 未单独采集 | 0.60 / 1.14 ms |
| 日志新增评分次数 | 本轮未插桩 | 0 |

新版完整方案数平均 516.9，最大 3316。129 回合里有 128 回合在保底之外检验到完整候选；仅保底出现在 B 面自然之灵、v1 先手对局的第 2 轮，当时只完成 1 次完整 V，束宽 6 尚未跑完。截止时保留其合法完整保底，未返回半回合。

“仅贪心保底”表示搜索没有另外检验到完整路径，不等于最终选中路径恰好与保底相同的比例。束宽是否完整完成另由 widthsCompleted 记录；一个尚未完成的束宽轮次仍可贡献已完成的方案。

CPU 是进程各线程之和，V8 并行 GC 等会使它超过墙钟时间。新版平均 CPU 时间和墙钟耗时都更多，并非靠更少总计算时间获得这些比分；它将更多可用预算花在当前回合，超时幅度则更小。旧版仍存在超过软预算的回合，因此本表不是严格硬截止的棋力比较。

### 与此前 v2 的关系

此前同组场景中，v2 对 v1 为 2 胜 6 负、平均 −10.625 分，Solo 平均 −8.5 分。本轮 v3 的结果改善为 4 胜 4 负、平均 −0.875 分和 Solo +4.25 分；v2 的保底占比 60/127，本轮 v3 为 1/129。

这不是 v2 与 v3 的直接对局或严格消融：运行时间不同，真实限时路径可能变化，而且评分口径从 v2 回到 v1，搜索范围、剪枝、缓存和日志也一起变化。可确认的是零日志补算、当前回合搜索覆盖和截止表现已达到本轮设计；尚不能据此宣称稳定的总体棋力优势。
