# NN + RL 小规模流程与速度测试

本报告保留 **`harmonies-rl-v1` 排序持牌 embedding 编码**的历史结果。当前代码已升级为 v2 固定卡牌 ID 三特征编码；本报告中的模型、轨迹与速度数字不适用于新 schema，旧产物也不能直接加载到 v2。

测试日期：2026-10-10 UTC（本机时间 2026-10-09）。结论：默认模型的**初始化 → 完整自博弈 → 训练 → checkpoint 续训 → JSON 导出 → 新一轮采样**已跑通。在本次小规模配置下，耗时主要在 MCTS 采样。

## 配置与计时口径

- Apple M4，10 个逻辑 CPU，24 GiB 内存；macOS arm64，Node.js 24.17.0，Python 3.12.14，PyTorch 2.6.0。
- 默认模型：两层 `128 → 128` FFN、8 维卡牌 embedding，392,707 个参数；不是此前集成测试用的 16×16 小网络。
- A 面、2 人、无自然之灵；初始随机网络 seed 41000。每组 8 局，环境 seed 41000–41007，交替先手。两种预算使用相同环境种子，但搜索造成的对局路径不同。
- TypeScript 单个 Node 进程采样；PyTorch CPU 单线程训练，batch 64，AdamW lr 0.001，10 epochs。各阶段串行运行，没有同时运行其他本任务的性能测试；未隔离系统后台负载。
- 采样核心时间包含搜索、特征编码、真实规则转移和终局标签回填，排除进程启动、模型加载、JSONL 序列化与写入。训练核心时间包含 batch 构造、前向、反向及 optimizer 更新，排除验证、文件读写和进程启动。端到端时间也单独记录。
- “样本”是一条原子动作决策，不是一个完整回合或一局。训练吞吐量会累计每个 epoch 对样本的重复使用。

## 数据收集速度

| 模型／每步模拟次数 | 局数 | 样本数 | 核心时间 | 含启动和 I/O | 秒／局 | 毫秒／决策 | 样本／秒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 初始模型／32 | 8 | 707 | 11.540 s | 11.657 s | 1.442 | 16.32 | 61.27 |
| 初始模型／128 | 8 | 704 | 45.437 s | 45.545 s | 5.680 | 64.54 | 15.49 |
| 训练后模型／128，新种子 | 2 | 180 | 11.690 s | 11.780 s | 5.845 | 64.94 | 15.40 |

前两组搜索吞吐分别约 1,961 和 1,983 次模拟／秒。模拟预算从 32 增至 128 后，每条决策耗时约增至 3.95 倍。初始模型单局耗时范围为 1.27–1.53 秒、5.20–6.46 秒；这些范围包含局长和局面差异，不是置信区间。

用于训练的前 16 局共 **1,411 条样本**，JSONL 总计 5,398,341 字节。训练后的额外 2 局共 180 条，用于确认导出模型可继续采样，没有混入此次训练。

## 训练速度

按环境 seed 留出验证数据；同一 seed 在不同搜索预算下生成的两个对局一起划分。训练集 14 局／**1,245 条**，验证集 2 局／**166 条**。每个 epoch 20 次 optimizer 更新，10 epochs 共 200 次更新、12,450 次训练样本使用。

从同一个 initial checkpoint 独立重复训练 3 次，使用相同数据、种子、配置：

| 重复 | 10 epochs 核心训练时间 | 训练吞吐 | 含启动、加载、验证、导出 |
| --- | ---: | ---: | ---: |
| 1 | 1.037 s | 12,006 样本／秒 | 2.314 s |
| 2 | 1.013 s | 12,285 样本／秒 | 2.225 s |
| 3 | 0.983 s | 12,664 样本／秒 | 2.206 s |
| 中位数 | **1.013 s** | **12,285 样本／秒** | **2.225 s** |

首次运行的 epoch 核心时间中位数为 0.101 秒；首个 epoch 为 0.134 秒，包含初次运行开销。首次运行加载数据 0.124 秒、总验证 0.101 秒、保存 `.pt` 和导出 JSON 0.107 秒。其余端到端开销包括解释器／PyTorch 导入、模型加载与 optimizer 初始化。

随后从训练后的 `.pt` 续训 1 epoch，更新步数从 200 增至 220，成功保留网络和 optimizer 状态。

这次 16 局的核心采样合计 56.98 秒，10 epochs 核心训练约 1 秒。因此在**当前小网络和数据规模下**，优先关注采样速度更有意义；以上数据不外推为大模型、GPU 或多进程的速度。

## 流程正确性与学习信号

- 全部 18 局、1,591 条样本逐动作使用真实引擎重放，检查合法动作全集、动作 ID、特征、访问次数、policy 概率和、终局得分及三个 value 标签，全部通过。
- embedding、两个共享 FFN 层和四个 head 的全部参数张量都发生更新；未出现 NaN 或无限损失。
- 使用此次默认模型的实际训练权重，在 88 个覆盖初盘／中盘／后盘的采样局面上核对 PyTorch 与 TypeScript。policy logits 最大绝对误差为 `5.96e-7`，三个 value head 分别为 `3.58e-7`、`2.24e-7`、`1.79e-7`。
- RL 的 9 项 TypeScript 测试、2 项 PyTorch 集成测试及 RL TypeScript 类型检查通过。

首次训练第 1 → 10 epoch 的损失：

| 目标 | 训练集 | 验证集 |
| --- | --- | --- |
| policy CE | 2.2052 → 2.1817 | 2.2277 → 2.2304 |
| rank MSE | 0.6382 → 0.0218 | 0.8195 → 0.9917 |
| relative MSE | 0.007463 → 0.000620 | 0.004522 → 0.003371 |
| absolute MSE | 0.008151 → 0.000470 | 0.002734 → 0.005209 |

训练集能够拟合，验证集未同步改善，已有过拟合迹象。这里只有一个验证 seed 的两个对局，不足以估计泛化或对局强度。本次不将损失下降或成功运行当作棋力提升，也不自动晋升这个模型。

## 复现与文件

新增 `rl/benchmark.py` 使用实际生产 CLI 串行运行测试；`scripts/rl.ts collect` 和 `rl/train.py` 增加结构化计时输出。可以在仓库根目录运行：

```bash
.venv-rl/bin/python rl/benchmark.py \
  --output rl/runs/benchmark-new \
  --games 8 --simulations 32 128 \
  --epochs 10 --train-repeats 3 \
  --seed 41000 --threads 1 --device cpu
```

输出目录必须不存在，避免把旧轨迹追加进新测试。报告包含运行命令、硬件、源码哈希、各 epoch 损失、分阶段耗时、每局耗时和吞吐。复现脚本负责生成、训练、续训和导出后采样；本次实际产物的全量重放与跨语言审计结果另保存在下面的文件中。

本次本机产物位于 `rl/runs/benchmark-20261010/`（目录已被 Git 忽略）：

- `report.json`：完整机器可读报告；`verification.json`：审计结果。
- `collect-32.jsonl`、`collect-128.jsonl`：实际训练数据。
- `initial.pt/json`、`trained.pt/json`、`resumed.pt/json`：初始化、训练、续训权重。
- `trained-collect.jsonl`：训练后新局面采样。
- `*.stdout.jsonl`、`*.stderr.log`：各阶段原始输出。
- `verify.mjs`：本次逐动作重放审计脚本；`parity-inputs.json`：88 个跨语言对照局面及 TypeScript 输出。

测试基于 `e993551` 后的工作区。工作区同时存在 B 面几何和 UI 的独立改动；本测试使用 A 面，其 23 格布局未变。实际执行文件的 SHA-256 已写入原始报告，便于区分代码状态。
