# 启发式 AI v2

本版不使用 RL、训练模型或远程 API。人类与 AI 共用规则引擎，规划在 Web Worker 中完成。完整实施规格见 [ai-v2-plan.md](ai-v2-plan.md)，验证结果见 [ai-v2-validation.md](ai-v2-validation.md)。

## 使用与时间预算

设置页可以选择 1–4 位人类或 AI 玩家，包括 AI Solo 和全 AI 观战。每位 AI 的参数独立保存：深度 1/2/3 个自身完整回合，默认 2；思考预算 1/3.5/10 秒，默认 3.5；每类日志 top-k 为 1/3/5，默认 3。程序配置还支持束宽 1–32，默认 6，以及固定种子，默认 1729。

深度包含当前剩余回合。先用完整 V 贪心生成合法的保底回合，再尝试束搜索与加深。深度 0 表示束搜索没有再检验到完整回合路径，使用的是保底；更深层必须完成所有根候选的两个场景比较才能提交。界面显示实际完成深度和耗时。

3500 ms 是软预算，包含保底的耗时。构造真实当前回合的完整保底、已经开始的单次估值必须完成；其余搜索按截止时间停止。没有额外的 35% 诊断阶段，日志复用搜索时的完整候选评分。240 ms 的逐步展示间隔不计入思考时间。

可以暂停/继续 AI。查看日志、规则或牌面详情会暂停执行。AI 回合禁止人工落子与撤销，人类自己的撤销和整回合重置保持可用。

## 唯一评分与项目

```
V = 当前规则总分 + 最多六个顺序项目的 sum(G*q)
局部 ΔV = V(after)-V(before)
G = 补建并入住后的规则总分 - 项目前的规则总分
```

所有中间节点、回合末节点、贪心保底和对手模拟均使用完整 V，没有动物增量专用的预筛选评分。

项目只有两类：已拥有未完成卡牌的一次合法補建入住，以及一枚合法地形放置。补建枚举六个旋转与所有合法建筑底层，严格匹配高度和堆叠前缀；已有动物的辅助格只能原样使用，入住落点必须空闲。

G 包括地形、动物和自然之灵的全部净变化；日志拆分 terrainGain/animalGain/spiritGain。仅保留 G>0 的项目。按折算值 W 选定一个项目后，在同一虚拟版图上执行、扣预算、先消耗手中 H，再消耗未来池 A，重新生成下一步候选。共享地形只计算新增成本和新增收益，落点占用会排除冲突项目。

颜色向量顺序为水、灰、棕、绿、黄、红：

```
m_c = 所需追加颜色数量，m=sum(m_c)
F=max(0,B-sum(H))
d_c=max(0,m_c-H_c)
p_c=sum(A)>0 ? A_c/sum(A) : 0
q=exp(-m/max(1,B)-0.5*sum(d_c*d_c/(1+F*p_c)))
W=G*q
```

m>B、sum(d)>F 或任意 d_c>A_c 时不可选。项目并列按 W（六位小数）降序、m 升序、规范坐标中的项目键升序。当前玩家未拿地形时，对每个完整供应组分别作为 H 完整估值，取最高 V；同分取组索引较小者。其他玩家的待放片不属于未来资源池。

V 是六项目启发式值，不是校准后的终局预测。q 也不是概率。拿地形前的 V 已经取最佳供应组，所以拿地形的局部 ΔV 可以为零或负；实际得分和潜力估计变化应分开理解。

## 结束轮次与预算

令 r 为当前轮次，a 为行动顺序索引，n 为人数，e_i 为空格数；当前玩家未拿地形时 u=3，否则 u=pending.length。继续近似每个完整回合占两个新格子：

```
当前玩家的 boardEnd = r+ceil(max(0,3*(e_i-2)-2*u)/6)
其他玩家的 boardEnd = r+[i<a]+max(1,ceil((e_i-2)/2))-1
bagEnd = r+floor((a+ceil(bagCount/(n===1 ? 9 : 3)))/n)
L = finalRound ?? min(bagEnd, ...boardEnd)
R = L-r+1
T_i = max(0,L-r+1-[i<a])
B_i = T_i===0 ? 0 : i===a ? u+3*(T_i-1) : 3*T_i
```

游戏已结束时 R/T/B 都是 0，V 等于规则分。T>0、B=0 仍可有无需补建的入住。普通 endTurn 不改变 L 与各玩家 B；真实落子、触发最后一轮可以改变预测。

## 规范朝向与缓存

将被评估玩家的版图转为 axial 坐标，在保持整个版图形状的旋转中，选择地形/动物内容编码字典序最小的朝向；禁止镜像。只在估值入口规范化一次，六个项目在同一朝向执行。返回项目通过逆变换映回真实格号。规则分与完整 V 在允许的旋转下保持不变。

每个 Worker 请求独立缓存完整估值、项目候选与规则分。完整 V 的缓存键包含规范版图、卡牌、被评估玩家、预算、供应与颜色池等全部语义输入。规则分缓存最多 8192 项，项目菜单最多 512 项；超出后移除最早加入的项。相同物理改动与入住的局部项目只保留最小并列键，此合并不改变分数或后续局面。完整 V 缓存不因 topK 改变。

规则引擎另缓存静态格子邻接关系，连通分组和河流仍从当前地形计算。没有改动计分规则，并与冻结的原计分实现做逐项等价测试。

## 搜索与信息边界

`observe` 只提供公开状态、观察者自己的自然之灵候选，以及从已知组件推算的袋子/牌库数量与组成。真实隐藏排列不传入 Worker。

一次展开计算所有合法动作后的完整 V，完成整个候选集合后才排序。若中途超时，不能从计算了一半的集合选动作。相同颜色的待放片只枚举一个索引。每层合并等价局面后保留前 beamWidth 个未完成节点，已完成回合单独保留前 beamWidth 个。分数并列依次比较当前规则分和动作序列。

深度 1 的 Q 是完整回合后的 V。后续深度使用两个公开信息抽样场景，种子分别为 `seed+rootRound*1009+rootPlayerId` 及该值加 7919。对手使用自身 V 贪心，未来自身回合束宽上限为 2。候选在两个场景中的最终 V 取平均得到 Q；整层未完成时保留上一层方案。转移缓存包含模拟袋子/牌库的排列，防止混用场景。

默认策略仍是最大化自身分数，不是胜率或对抗扣分。束搜索不保证最优，增加深度也不保证每次更强。保留平均占两格、未来颜色池、六项目贪心、有限束宽和贪心对手这些明确近似。

## 日志与兼容

“操作记录”中可导出 JSON，格式版本 2，估值版本 local-projects-v2。每个执行决策包含公开操作前局面、before、selected、每种操作全部合法候选中的 top-k，以及项目 G/m/d/p/B/F/H/A/q/W、收益拆分、L/T 和规范旋转。evaluatedCounts 必须等于 legalCounts；选中动作始终另存。

同一规划的动作通过 planId 关联。首个执行动作保存 planSummary：根局面 V、方案 Q、Q-rootV、完成深度、耗时、动作展开数、实际完整评分次数、停止原因，以及前 k 个完整方案的动作序列和场景分数。后续动作界面可查看同一计划摘要。

UI 区分即时规则分变化、潜力变化、局部 ΔV 与完整方案 Q。endTurn 涉及随机补充时，估值标明模拟抽样和种子；真正执行后由主线程另记 actualScoreAfter。未执行计划不写入日志。

旧 v1 决策保持原始数值，缺少版本字段时视为 v1；界面仍说明旧 top-k 是剪枝后的范围。混合导出通过每条 evaluationVersion 和顶层 evaluationVersions 区分。纯人类对局也可导出。

游戏/操作记录保存在 localStorage 的 harmonies.session.v1；AI 日志另存 IndexedDB harmonies-logs/sessions，以会话 UUID 关联。恢复日志后才继续 AI。

## 验证与基准

```
npm test
npm run test:e2e
npm run build
AI_BENCH_MODES=ai npm run benchmark:ai
```

基准使用 Solo A seed=11、Solo B+自然之灵 seed=13、双人 A+自然之灵 seed=17、四人 B seed=19，检查动作、资源守恒、等回合数与完整结束。默认结果保存到 `/tmp/harmonies-ai-v2-benchmark.json`；`AI_BENCH_MS`、`AI_BENCH_TOP_K` 和 `AI_BENCH_OUTPUT` 可覆盖预算、日志数量和路径。省略 AI_BENCH_MODES 时，还运行随机/即时规则分贪心对照。

测试可提供恒定时钟和固定未缓存评分计算上限。保底计入计算次数但不被上限截断；其余搜索遵守上限。固定公开局面、种子、参数、计算上限得到相同方案；topK 不改变方案。真实限时的搜索覆盖范围会随设备负载变化。
