# AI v2 改进实施规格

本文件保留已确认的实施规格；功能已落地，实际验证见 [ai-v2-validation.md](ai-v2-validation.md)，运行说明见 [ai.md](ai.md)。针对 local-projects-v1 的日志审计结果，统一估值、搜索与诊断口径，修正剩余预算与版图方向偏差。继续使用启发式方法，不引入 RL。

## 1. 决策目标与固定参数

唯一局面评分为：

```
V(s, player) = scorePlayer(player, side).total + sum(selectedProjects.W)
localDeltaV(action) = V(after, player) - V(before, player)
```

所有搜索中间节点、贪心保底、对手模拟和回合末节点均使用这个 V。删除 `orderValue`，不保留只计算动物增量的第二套评分。

深度 1 的完整回合分数 Q 为该回合结束后的 V。深度 d>1 的 Q 为两个抽样场景中，完成第 d 个自身回合后的 V 的算术平均；场景提前终局时使用终局规则分。选择 Q 最大的已完成方案。不累加不同步骤的 V，也不将局部 ΔV 求和作为跨回合目标。

保持配置默认值：depth=2、timeMs=3500、beamWidth=6、topK=3、seed=1729。保留现有配置范围。深度包含当前剩余回合；topK 只控制诊断的保存数量，不控制搜索宽度。

用于排序的所有浮点分数先计算 `Math.round(value * 1e6)`；日志保留未舍入值。搜索节点并列时依次比较：V/Q 降序、该节点当前规则分降序、动作序列升序。深层完整方案 Q 并列时，“当前规则分”固定指该根候选完成当前回合时的规则分，不使用某个抽样场景的分数。动作序列使用现有 `compareActions` 的数值字典序；一个序列为另一个的前缀时，较短者在前。

## 2. 以绝对结束轮次修正剩余预算

新增纯函数 `estimateHorizon(view)`，返回预计结束轮次 L、各玩家剩余回合机会 T 和地形放置预算 B。每次只依赖当前公开局面，不冻结搜索根节点的预算，不读取历史日志。

定义：

- r：当前轮次，从 1 开始。
- a：当前玩家在行动顺序数组中的索引，从 0 开始；不是 player.id。
- n：玩家人数。
- e_i：玩家 i 当前空格数。
- u：当前玩家本回合剩余必放地形数；未拿地形时为 3，已拿时为 pending.length。
- `[condition]`：条件成立为 1，否则为 0。

保留“每个完整回合平均占用两个新格子”的近似。未结束游戏中，因各玩家版图预计触发终局的轮次为：

```
当前玩家 i=a：
  boardEnd_i = r + ceil(max(0, 3*(e_i-2) - 2*u) / 6)

其他玩家 i!=a：
  firstRound_i = r + [i<a]
  requiredTurns_i = max(1, ceil((e_i-2)/2))
  boardEnd_i = firstRound_i + requiredTurns_i - 1
```

当前回合剩余 u 枚预计占用 `2*u/3` 个空格；使用上述整数形式避免浮点边界误差。当前玩家放完地形、空格仍大于 2 时，预计触发回合必然在下一轮或以后。其他玩家已经触发的真实终局由 finalRound 优先处理。

地形袋触发轮次按规则引擎当前的补充时点计算：袋子已空的回合结束触发；抽走最后一组本身不触发。令：

```
refillSize = n===1 ? 9 : 3
refillsUntilEmpty = ceil(bagCount / refillSize)
bagEnd = r + floor((a + refillsUntilEmpty) / n)
```

结束轮次与预算：

```
如果 phase==='ended'：T_i=0，B_i=0，R=0，V=当前规则分。
否则：
  L = finalRound ?? min(bagEnd, ...boardEnd_i)
  R = L-r+1
  T_i = max(0, L-r+1-[i<a])
  B_i = T_i===0 ? 0
        : i===a ? u+3*(T_i-1)
        : 3*T_i
```

R 继续表示包含当前轮在内的预计剩余轮数；日志另记 L 和被评估玩家的 T。

关键约束：普通 `endTurn` 只切换行动玩家、补充供应，未结束游戏时，L 与每位玩家的 B 不变。拿地形不改变 B；实际落子可因空格变化而调整预计终局。最后一轮已行动的玩家 T=0，尚未行动者仍保留本轮机会。B=0 且 T>0 时，仍允许无需补建的入住项目。

已在用户提供日志的 8 次非终局 AI endTurn 上验算此公式：每次前后 L、所有玩家 B 均相等。第 8 轮 AI 的 B 为 3→3，不再是 0→3。

## 3. 完整估值与资源折算

项目种类保持两个：已拥有且未完成卡牌的一次补建入住；一枚合法地形放置。动物/自然之灵补建仍枚举全部合法起点、六个旋转及建筑底层，严格使用当前 `projects`、`canPlace` 和卡牌高度规则。

每个候选项目的收益都计算为：

```
next = applyProject(virtualPlayer, project)
G = scorePlayer(next, side).total - scorePlayer(virtualPlayer, side).total
```

只保留 G>0。G 包含动物档位、全部地形净变化和自然之灵净变化。日志新增 `terrainGain`、`animalGain`、`spiritGain`，分别取两次规则分的 landscape、animals、spirit 差；三者之和必须等于 G。

颜色向量顺序仍为水、灰、棕、绿、黄、红。当前玩家未拿地形且 T>0 时，将每个完整供应组分别作为 H，独立运行完整估值，选择 V 最大的组；并列选组索引最小者。已拿地形时 H 为实际 pending；评估非当前玩家时 H 为零。A 为公开推算的袋中颜色数加供应板颜色数，再扣除已经作为 H 的供应组。其他玩家的 pending 不属于 A。

以下折算不变，全部基于每一步尚未消耗的资源：

```
m_c = 项目追加颜色 c 的数量
m = sum(m_c)
F = max(0, B-sum(H))
d_c = max(0, m_c-H_c)
p_c = sum(A)>0 ? A_c/sum(A) : 0
q = exp(-m/max(1,B) - 0.5*sum(d_c*d_c/(1+F*p_c)))
W = G*q
```

若 m>B、sum(d)>F 或任意 d_c>A_c，排除项目。T=0 不生成未来项目。

最多选择 6 个项目。每一步重新生成全部候选，按 W 降序、m 升序、项目数值键升序选第一名；没有合格项目就停止。执行选中项目，扣除 B，逐颜色先消耗 H、不足部分消耗 A，再计算下一步。项目数值键继续采用现有格式，但在下节的规范坐标中生成。

共享地形只在第一次实际补建时产生边际收益和资源成本；入住后该落点被占用，其他项目必须重新检查合法性。保留既有近似：只估已持有卡牌、最多 6 个贪心项目、未来供应用颜色池表示、独立零/负收益地形铺垫不作为局部项目。外层搜索仍可执行零/负局部收益的真实动作。q 是启发式折算系数，不宣称为概率。

## 4. 消除同一版图旋转后的估值差异

不新增多路径局部搜索；在估值入口先把被评估玩家版图变换到唯一规范朝向，再运行第 3 节算法。只使用保持完整版图形状不变的旋转，禁止镜像。

规范化算法固定如下：

1. 以原版图 cell 索引顺序作为目标格顺序。将 offset 坐标转为 axial：`q=col, r=row-floor(col/2)`。
2. 枚举 k=0..5。对所有格子应用 k 次旋转 `(q,r)->(-r,q+r)`。
3. 对每次旋转，只尝试平移 `dq=minOriginalQ-minRotatedQ`、`dr=minOriginalR-minRotatedR`。平移后整个坐标集合与原版图集合完全相等时，保留该格子置换；否则丢弃。
4. 将版图内容按置换放入原目标格顺序，每格编码为固定长度数值元组 `[tokens.length, tokens[0]??0, tokens[1]??0, tokens[2]??0, animal??0]`，拼接为数值数组。
5. 取数组数值字典序最小的朝向。完全相同则选 k 较小者。卡牌、资源、玩家身份、行动顺序不变。
6. 在该版图上生成项目并完成全部六步贪心，不在六步之间再次改变坐标系。将返回项目的补建格和入住格经逆置换映回真实版图。保存 `canonicalRotation`；项目 key 明确表示规范坐标中的排序键。

规范版图缓存保存规范坐标中的评估结果，返回前再映回调用方坐标，防止缓存命中后日志格号错误。

保证的是完整 V 在合法旋转下相等，不承诺并列动作一定旋转等价，也不承诺启发式 V 等于真实终局最优分。整棵限时搜索仍受剪枝和时间预算影响。

## 5. 用同一 V 完成搜索与保底

`expand(state, actor)` 的定义：枚举全部合法原子动作，应用动作，为每个不同子局面计算完整 V；相同子局面可复用缓存，但每个不同动作都保留候选记录。不得在完整 V 之前按分数淘汰任何动作。

一次展开必须全量完成，才可用于选择和日志。超时中断的展开不得用已计算的前半部分选择动作；已完成的估值可保留在缓存。

真实当前回合先生成一个完整保底方案：重复全量 expand，按第 1 节排序选第一名，直到 endTurn。其每一步都是完整 V 贪心；不再使用便宜评分。沿用 64 个原子动作的异常保护上限，超过时返回显式错误，不提交半回合。

完整回合束搜索：

1. frontier 初始只含根局面。complete 初始包含保底完整回合。
2. 按上一层排序顺序，全量展开 frontier 中每个节点。
3. endTurn 子节点写入 complete；同局面保留排序更优的动作序列。
4. 其他子节点合并、按公开局面去重后，按完整 V 排序，仅保留前 beamWidth 个作为下一层。
5. 不再执行“每个父节点先保留 6 个”或“每种操作类型额外保留一个”的预筛选。
6. frontier 为空、达到预算或 64 层上限时停止。保留所有已经发现的完整回合；完整回合池仅需保存最优 beamWidth 个不同终局面。
7. 如果一层只展开了部分父节点，已完成的 endTurn 候选仍可保存，但不从不完整的下一层继续扩展。选当前已知 Q 最大的完整回合。

深度 2/3 保留现有公开信息抽样模型：场景种子为 `seed+rootRound*1009+rootPlayerId+sampleIndex*7919`，sampleIndex=0,1。深度 1 使用第 0 个场景。将深度 1 的前 beamWidth 个完整方案（含保底参与排序）作为固定根候选池。

对每个根候选、每个场景重新从抽样根局面重放当前回合，然后模拟后续回合。对手用其自身完整 V 的单步贪心；未来自身回合用同一套束搜索，宽度为 min(2, beamWidth)，先生成该未来回合的完整 V 贪心保底。所有未来展开均受预算约束。提前终局时停止该场景并返回最终规则分。

每个深度必须完成全部根候选的两个场景，才按平均 Q 替换上一深度结果；否则丢弃该层的候选排名，保留上一深度方案。各候选的场景分数和平均值要留作诊断。对手采用自身分数目标，不引入对抗扣分或胜率模型。

保留 completedDepth=0 表示只完成了当前回合的贪心保底、束搜索未检验到任何完整回合路径。束搜索检验到至少一条根到 endTurn 的路径后，深度 1 计为完成；该路径允许与保底相同。更深层完成按前述全候选、全场景条件判断。分支提前终局可视为完成该层目标，日志标注 terminal，不虚构后续动作。

## 6. 时间预算、缓存和确定性

取消 65% 搜索、35% 事后诊断的划分。计时从 Worker 开始该次规划时起算，timeMs 用于保底之后的束搜索和加深；保底消耗同一个总计时，并非额外赠送 timeMs。

默认仍为 3500 ms 的软预算：真实当前回合的完整贪心保底必须完成；之后在每个候选完整估值开始前及新层提交前检查截止时间。一项已经开始的 evaluatePosition 执行完再检查。预算耗尽时不启动新的搜索展开，返回已知最佳完整方案。未来模拟没有免限时保底。

因当前回合保底和单次估值不能随意截断，不能承诺严格 3500 ms。界面与日志保留实际耗时及 fallback/timedOut；不为满足时间而改用第二套评分。普通决策目标仍是 2–5 秒，简单终局允许更快。

缓存限定在一次 Worker 规划中：

- 完整估值：评估玩家 ID + 规范化后的完整公开局面键；包含预算公式所用轮次、行动玩家、pending、finalRound、bagCount，以及颜色池和卡牌状态。明确排除真实隐藏排列。
- 项目图案：沿用按版图几何形状和卡牌 ID 预计算的旋转模板。
- 规则分：side + 版图每格完整堆叠/动物 + 卡牌 ID/placed。不得只按地形顶部颜色缓存。
- 状态转移：公开局面键之外仍包含模拟袋子、牌库的排列，不能把两个抽样未来合并。

评分缓存命中不重新耗费评分节点额度；另记动作展开数和真实评分计算数。测试用固定评分计算数量上限和恒定时钟，候选按现有动作数值顺序展开。当前回合保底不因测试上限而被截断，其计算计入总数；保底后达到上限即停止搜索。相同公开局面、种子、参数和固定计算上限必须得到相同方案。

## 7. 日志、界面与兼容

导出格式 version=2，evaluationVersion=`local-projects-v2`。保留旧日志原值，不用 v2 重新解释 v1 数字；无版本字段的旧 AI 决策视为 v1。旧存档、IndexedDB 中旧决策及纯人类日志仍可查看和导出。

每个实际执行的决策点，直接使用搜索时该局面全量展开的结果，按操作类型分组，用完整 V 降序、当前规则分降序、动作键升序保存前 k 个。同类不足 k 个时全部保存。selected 永远单独保存。计数必须满足 evaluatedCounts[type]===legalCounts[type]；不能把未算完的集合标为完整 top-k。日志不启动第二轮便宜评分筛选。

保留 before、selected、topByOperation 及项目变量 G/m/mByColor/d/p/H/A/B/F/q/W；新增 L、T、terrainGain/animalGain/spiritGain、canonicalRotation。所选动作另记规则分变化、潜力变化，二者之和等于局部 ΔV。

每次 Worker 规划生成 planId，由主线程以 `session.id + ':' + 本次规划开始时 game.log.length` 分配。各实际动作引用同一 planId，带 decisionIndex。该计划首个执行动作额外记录 planSummary：根局面 V、目标/完成深度、完整方案 Q、Q-rootV、耗时、展开/评分数量、停止原因，以及最后完成深度中前 topK 个完整方案的动作序列、Q、场景分数。若仅有保底，则候选只有保底。未执行、被暂停丢弃的计划不写游戏日志。

UI 使用明确名称：

- “即时规则分变化”。
- “局部估值变化 ΔV”；说明它包含潜力重新估计，允许负值。
- “完整回合／多回合搜索值 Q”和“计划相对根局面的估值变化”。
- “每类全部 N 个合法动作已估值，显示前 k 个”。

不将负 ΔV 标成错误或劣着。未拿地形时，before 仍是各完整供应组中的最高估值，因此拿地形的局部 ΔV 可以为零或负。

候选评分始终表示决策当时的估算。若 endTurn 会补充随机地形/卡牌，明确记录 `usesSampledRefill` 和场景种子，UI 标记“补充资源按模拟抽样估计”；不把模拟补充后的 V 标成真实执行后的复算值。主线程在真实 applyAction 后另记 actualScoreAfter。

topK 不影响展开、估值、缓存填充和搜索时间检查；只在方案已选定后截取缓存结果并序列化，保证改变 topK 不改变相同固定预算下的实际方案。

## 9. 验收标准

逻辑回归：

- 对 1–4 人、A/B 面、拿片前/拿片后/放完地形/最后一轮建立预算测试。非终局 endTurn 前后，每位玩家 B 相等；轮次跨越后 L 相等。Solo 袋中剩 3、6、9 片，及多人补完袋子的边界单独覆盖。
- 取用户日志的 8 个非终局 endTurn 作为固定回归局面，全部满足上述预算不变约束。第 8 轮 B=3→3。
- 项目 G 与规则引擎总分差相等；三项 gain 相加等于 G。共享建筑不得重复计地形收益；共享辅助格不得重复耗片；入住落点不可重复使用。
- A/B 面分别枚举规范化函数认可的所有旋转，确认 V 相等至 1e-9；返回项目映回原坐标后仍可合法执行。该日志第 1 轮树冠位于 1-1/5-5 的两个局面 V 必须相等，不锁定旧版本的数值。
- 每个参与剪枝的子节点，其记录分数必须等于独立调用 evaluatePosition 的结果；不存在动物增量专用排序。
