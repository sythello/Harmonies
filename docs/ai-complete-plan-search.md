# 以完整方案为单位的预算搜索：待确认实施计划

本文件是设计计划，不修改当前 AI。目标是在相同时间预算内，优先完成可比较的完整回合方案，避免把大部分时间投入不能提交的宽搜索或深层比较。保留启发式方法，不引入训练或 RL。

## 1. 完成条件与时间约束

这里区分三件事：

1. **可执行方案完整**：从当前状态出发，包含本回合剩余动作，恰好以一个 endTurn 结束，每一步合法。
2. **候选比较完整**：参与最终排名的每个候选，都已完成相同深度、相同两个随机场景的计算。部分场景结果不得混入平均分。
3. **预定工作单元完整**：正常调度只在工作单元之间停止。启动前判断剩余预算能否容纳整单元，不在正常路径中逐节点抛超时异常。

不把“完整”解释为穷举全部合法策略，也不承诺任意设备都能在 3.5 秒内完成深度 3。宽度、实际深度由可用时间决定；输出的动作方案和已提交的比较必须完整。

普通浏览器、操作系统调度和垃圾回收没有可证明的最坏耗时上界。因而不能同时绝对保证“任何已启动计算均完成”和“任意条件下硬性不超过 N 毫秒”。本计划采用：正常流程预测准入并完整执行；异常延迟由主线程截止保护，返回已经收到的完整检查点。日志区分这两种停止原因，不把硬中断说成正常完成。

## 2. 可选实现方式与选择

| 方式 | 规则 | 主要限制 |
| --- | --- | --- |
| 开始前固定整批规模 | 预测成本，先确定候选数/深度，整批运行完再返回 | 单批成本估错时仍会超时；当前全量 V 贪心的最低成本仍高 |
| 逐个完成方案并增量比较（采用） | 同一深度下，一个新方案算完两个场景就进入排名；加深只先比较两个方案 | 候选空间需要显式限制，不能声称全空间最优 |
| 保留原束搜索，仅动态降宽/降深 | 保持所有中间节点完整 V 排序，根据历史耗时选束宽与深度 | 改动小，但在昂贵的单次展开中仍可能中断，完整 V 保底仍可能吃掉预算 |

采用第二种，并增加第一种的成本准入。改变搜索任务的粒度，而不只调整原来 65%/35% 一类时间比例。

## 3. 唯一最终决策目标

保留 v2 完整估值，称为 V6：当前规则分加最多六个顺序项目的折算收益。预算公式、G 的地形/动物/自然之灵增量、规范朝向、资源共享与入住冲突处理均不改。

对完整当前回合方案 P 定义：

```
Q_d(P) = (V6(S(P, d, 0)) + V6(S(P, d, 1))) / 2
```

S 是从当前局面开始，执行 P，并完成第 d 个自身回合后的模拟局面；提前终局使用终局规则分。d 包含当前回合。两个场景使用原种子公式：seed + rootRound*1009 + rootPlayerId + j*7919，j=0,1；同一次规划所有候选共用这两个场景。深度 1 也使用两个场景，明确替换当前深度 1 只用场景 0 的做法。

后续自身与对手回合统一使用第 4 节的 E1 贪心，只最大化行动者自身评分。未来自身回合不再递归开启宽度 2 的束搜索。这是明确的速度/精度取舍，深度参数仍表示向前推演多少个自身完整回合。

同一深度内按 round(Q*1e6) 降序、完成当前回合的根玩家规则分降序、动作序列数值字典序升序选择。不同深度的 Q 不互相直接比较。每次加深成功后，以新深度的完整比较结果替换旧深度结果。

## 4. 候选生成策略 E1

需要降低“先得到一个完整方案”的成本。引入明确标注的候选生成评分：

```
E1(s, actor) = 当前规则分 + max(0, max_合法单项目(G*q))
```

它就是 V6 估值流程的**第一轮项目选择**，保留全部项目种类、地形/动物/自然之灵净增量、m/d/p/B/F 公式和合法性检查。未拿地形时仍分别计算所有完整供应组并取最大值。没有顺序执行后续五个项目。不是旧版“每张牌最佳一次动物收益相加”的评分。

实现中参数化项目步数为 1 或 6，缓存键包含步数；不修改默认完整估值语义。E1 仅用于生成候选及模拟未来策略，最终方案排名只用 Q/V6。

E1 贪心：每个决策点枚举并计算全部合法动作的 E1，按六位小数 E1 降序、规则分降序、compareActions 升序选第一个，直到 endTurn。保留 64 动作异常保护；超限视为实现错误，不能假装完成。已完成一次展开的全部 E1 评分保存在请求缓存中。

完整候选按以下唯一流程产生：

1. 在场景 0 上生成 E1 贪心完整回合 P0，并记录每个前缀处所有动作的 E1 排名。
2. 对 P0 的每个非结束状态，把除所选动作外的合法动作加入偏离队列。队列项是“照走 P0 的此前前缀 + 强制一个不同动作”。
3. 队列排序键为该前缀第一名 E1 减该替代动作 E1（六位小数，升序）、前缀长度升序、替代动作数值键升序。
4. 依次取队首，执行该偏离，再用同一 E1 贪心补到本回合结束，得到新的完整方案。偏离动作本身是 endTurn 时直接完成。
5. 按场景 0 的完整结束局面 positionKey 去重，保留首次出现者。不扩展这些替代方案的新偏离，只枚举 P0 的单次偏离邻域。
6. 最多保留 K 个不同方案，K=beamWidth（默认 6）；最多尝试 4*K 个偏离项。次数达上限与队列自然耗尽分别记日志。

这显式限制了候选空间，没有对全部回合策略求最优的承诺。E1 可能排除最终更好的方案，必须由强度对照验证此取舍，不能把更快完成等同于更强。

## 5. 完成次序

### 5.1 主线程先准备合法应急方案

在创建 Worker 前，用公开局面构造确定性当前回合方案：有自然之灵选择时选最小卡号；未拿地形时选最小完整供应组索引；有待放片时按 pending 索引及 cell 索引升序选择合法放置；满足结束条件时立即 endTurn。不主动拿动物牌或入住。

该路径不计算 E1/V6，不进行搜索，是启动失败或严重延迟时的应急检查点；界面和日志明确标为“应急方案，未完成候选比较”，不填造 V 或搜索深度。正常有效游戏若不能补成完整回合，报规则状态错误，不提交半个回合。

### 5.2 尽早完成第一轮真实比较

1. 准入允许时，生成 P0 并完成两个场景的 Q1；保存并发送完整检查点，标记仅一个候选。
2. 准入允许时，生成并评估第一个不同的方案 P1；两个方案均有完整 Q1 后立即比较并发送检查点。
3. 若偏离队列耗尽、尝试次数达到 4*K 或 K=1，只保留已经完成的结果，不虚构第二个候选。

### 5.3 先小规模加深，再增加方案

有 P0/P1 后，按固定顺序执行：

```
两个方案，深度 1
→ 两个方案，深度 2（目标深度允许且整个单元能准入）
→ 两个方案，深度 3（目标深度允许且整个单元能准入）
→ 在已完成的深度 D 上，逐个增加 P2、P3……，最多 K 个
```

每次加深将 P0/P1 的两个场景一起作为一个小单元。全部完成前沿用前一深度的比较结果。加深不能准入时立即停止加深，尝试在当前深度新增方案；不会因此结束全部搜索。

扩展宽度时，每个新方案完成当前深度 D 的两个场景，立即纳入比较，不等待剩余 K 个方案。因此不存在“第 6 个候选超时，前 5 个同深度评分全部失效”的正常行为。扩宽后不再次对整个候选池加深。

每个候选保存两个场景在各已完成深度的结束状态。加深只模拟新增的那一轮，不重复模拟此前回合。完整 V 的评分缓存照常复用。提前终局的场景后续直接沿用终局分。

## 6. 预算准入：固定算法

时间预算从主线程准备该请求时开始，包含应急方案、Worker 启动、搜索和检查点消息。绝对时间使用 performance.timeOrigin + performance.now()，主线程把截止时间传给 Worker。

```
B = timeMs
reserve = max(100 ms, 0.10*B)
workDeadline = requestStart + B - reserve
hardDeadline = requestStart + B
```

保留时间用于日志截取、消息传递和主线程接收，不再运行额外评分。预算过小导致 workDeadline 已过时，直接使用已准备的应急方案。

每个 Worker 请求独立计量：E1 完整回合生成耗时、单次完整 V6 调用耗时。每类最多保存最近 16 次完成的测量，包含缓存命中调用：

```
tTurn = max(100 ms, 最近最多 16 次 E1 回合耗时的最大值)
tEval = max(20 ms, 最近最多 16 次 V6 调用耗时的最大值)
estimatedCost = 1.5 * (Nturn*tTurn + Neval*tEval + 10 ms)
准入条件：now + estimatedCost <= workDeadline
```

无历史样本时分别使用 100/20 ms。上述值是初版固定参数，不冒充耗时硬上界。每次单元完成后记录预测/实际耗时比；若未达到验收目标，调整必须在报告中列明，不能隐式缩减 V6 精度。

单元工作量：

- 新候选的生成阶段最多一个 E1 剩余回合，Nturn 加 1。重复结束局面立即跳过评分；每个偏离尝试单独准入，不预先假设一次就能得到不同方案。
- 两个场景的当前回合仅重放已生成动作，不再次运行 E1，作为 10 ms 固定开销及 reserve 的一部分。
- 从未评分候选计算 Q_d：未来完整回合的预计数量为 2*n*(d-1)，Neval=2。
- 从已完成 Q_(d-1) 升至 Q_d：新增 2*n 个未来回合，Neval=2；两个候选一起加深时将这两项乘 2。
- 提前终局、缓存复用只减少实际工作，准入估计仍使用上述保守计数。

生成新候选前同时计入生成和目标深度评分的预计成本，避免只生成一批无法评分的候选。生成成功后再次确认评分剩余成本能准入；若不能，则结束本次搜索并返回已提交方案，记录生成工作的未使用耗时。这属于估计失准的明确例外，不算候选比较完成。

正常流程不在一个已准入单元内部抛 BudgetExceeded。每个完成单元立即准备并 postMessage 完整检查点，之后才决定启动下一单元。

主线程到 hardDeadline 时结束 Worker，并选择截止回调运行时已收到的最新完整检查点；没有收到评分检查点时选择预先准备的应急方案。浏览器主线程自身也可能延迟调度，因此只能承诺应用级截止保护，不能承诺操作系统级硬实时。

异常硬中断最多损失当前一个单元：普通扩宽是一个候选，加深是两个候选的小批次。此前同一深度已完成的候选和已提交深度不丢弃。不重算日志，不在超时后启动新贪心。

## 7. Worker、日志与 UI

Worker 消息改为带 requestId、positionKey、revision 的 checkpoint / done / error。主线程只接受当前请求、当前根局面的消息；checkpoint 仅保存，收到 done 或截止保护触发后才执行动作。暂停、换局、撤销会取消请求，迟到消息忽略。

UI 同时显示“比较了几个完整方案”“实际前瞻深度”“是否发生硬截止”，不再仅用 completedDepth 推断完成质量。一个候选和两个以上候选分开标记；应急方案单独标记。

**本计划需要明确调整 v2 的日志约定：**

- 操作级 top-k 是全部合法动作按 E1 的排名，清楚写“候选生成评分 E1”；不得标成全部动作的完整 V6 排名。
- 方案级 top-k 是已经完成相同深度、两个场景的完整方案按 Q 排名；清楚写“已完成 N 个候选方案中的前 k 个”。不声称覆盖所有合法回合策略。
- 完整 V6 的 m/d/p/B/F/G 与六项目明细保留在完整方案的场景终点评估中。E1 操作日志仅有第一项目的同类变量。
- 规则分变化仍由实际执行记录；不拿 E1 的变化冒充完整 V6 的 ΔV，也不把本回合真实得分与模拟未来分混为一谈。
- 新增 strategyVersion、评分类型、候选生成范围、已完成候选数/场景数、深度、成本预测与实际值、准入拒绝、硬中断及未使用工作耗时。
- 新日志采用明确的新类型/格式版本，旧 v1/v2 数值及显示语义原样保留。topK 只决定保存数量，不参与候选生成或评分。

为了维持“每一步所有合法动作都用 V6 评分”的旧约定而在搜索结束后补算日志，会重新引入主要耗时，本方案不采用该做法。

## 8. 实施范围与顺序

1. evaluate.ts / types.ts：参数化 1/6 项目估值、分离评分类型及缓存。
2. 新增 turn-policy.ts：确定性应急方案、E1 贪心、单偏离候选生成。
3. 新增 budget.ts：单元工作量、耗时测量、准入算法及可注入时钟。
4. 新增 search-complete.ts：完整方案 Q、两个候选加深、同深度增量扩宽、场景状态复用；现有 search.ts 保留为 v2 基线。
5. worker.ts / useAI.ts：检查点协议、请求校验、截止保护、取消与恢复。
6. GameLog.tsx / log.ts：新旧日志兼容、E1/Q 分离、完成度与预算诊断。
7. 策略选择与基准：新增独立策略 complete-plans-v3，设置页可选择；v2 作为已有对局和缺省配置的策略。保留 v1/v2 对照入口，本计划不根据小样本成绩自动切换默认策略。

## 9. 验收标准

正确性：

- 每个可提交检查点重放后恰好合法结束当前回合；无半回合计划。
- 同一候选排名集合中的所有 Q，深度与两个种子完全一致；独立重放复算相等。
- 加深复用已完成状态与从根完整模拟得到的状态/分数相等。
- E1 等于 V6 算法仅执行一次项目选择的结果；不能串用 1/6 项目缓存。
- 在每个阶段边界及单元内部注入时钟突增/Worker 终止，已有完整结果保留；硬截止不启动补救搜索，不等待日志补算。
- 固定工作量模式下，同种子/同局面/topK=1/3/5 返回相同动作；该模式预先指定候选数与深度，完整执行且不受真实机器耗时影响。
- 旧日志、新日志、暂停/继续、刷新、晚到消息和纯人类对局导出测试通过。

预算与完成率：

- 默认 3500 ms，在 v2 同一组固定完整对局上，至少 95% 的规划完成两个不同方案的同口径比较；“实际动作完整”必须为 100%。
- 准入后被主线程硬中断的请求比例不超过 1%；应急方案单独统计，不把它计作正常搜索完成。
- 应用级实际耗时 P95 <= 3600 ms；记录最长耗时及浏览器调度延迟，不隐藏超限样本。把正常准入拒绝与预测失败的硬中断分别统计。
- 深度 1/2/3 分别报告，不把“设置了深度 3”当作实际完成。

强度：

- 先复跑原有四组种子的 8 场交换座位双人局和 4 组 Solo 配对，与 v1/v2 同可用时间预算比较实际终局分，并列出实际耗时。
- 小样本回归后再运行独立验证集：A/无自然之灵 seed=23、41；B/无自然之灵 seed=29、43；A/有自然之灵 seed=31、47；B/有自然之灵 seed=37、53。每组 v3 分别对 v1/v2 交换座位，Solo 三版分别运行，共 32 场双人局和 24 场 Solo。不根据单个种子的结果调参。
- 强度结论与完成率结论分别报告，给出逐种子的配对分差、均值、胜负及实际耗时，不以这些有限样本宣称普遍优势。首次实施验收以完成条件和预算指标为准；强度回退必须直接写明，不能只报告完成率。

需要确认的核心取舍是：**操作级候选生成由完整 V6 改为明确标注的 E1；完整 V6 保留给同口径的完整方案比较。** 如果坚持所有原子动作必须先计算完整 V6，预算调度仍可改善，但无法承诺解决当前贪心准备阶段本身昂贵的问题。
