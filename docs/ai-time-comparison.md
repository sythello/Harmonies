# AI v1 / v2 相同思考预算对照

历史结果保留。当前 `benchmark:compare-ai` 已改为 v1/v3 对照，见 [ai-v3-time-comparison.md](ai-v3-time-comparison.md)；以下命令与当前版描述对应当时的 v2 实验。

本批结果：**新版在双人局 2 胜 6 负，平均少 10.625 分；Solo 四组平均少 8.5 分。** 这批数据没有显示 v2 的强度提升，反而显示同预算下的回退。样本仅为预先固定的四组种子，不能推断所有局面的胜率。完整原始数据见 [ai-time-comparison.json](ai-time-comparison.json)。

## 旧版与对照范围

旧版完整保留在 Git 提交 `f36c7ccada107220867722f460c67da02215c91b`（`init add heuristic ai`）中。`scripts/compare-ai.ts` 每次用 `git archive` 提取该提交的 `src/game` 到独立临时目录，运行未修改的 v1 搜索、估值及计分实现，结束后删除临时副本；不会切换当前工作区或覆盖 v2。

这里比较的是旧版与当前版的完整 AI 实现，包括它们各自的剪枝、估值、日志耗时和计分性能优化。真实对局由同一个当前规则引擎执行，每次动作验证合法性与各颜色地形/动物牌守恒；每个回合用新旧规则计分器逐字段复核一致。两个 AI 均只收到公开观察，不能读取真实袋子或牌库排列。

此前的 [固定评分次数审计](ai-v2-audit.json) 用于核查逻辑，不能替代本次耗时与强度比较。不同版本的 V/Q 定义不同，因此本次使用实际终局规则分及正式胜负，不比较它们的 V/Q 大小。

## 预先固定的实验

- 两版配置相同：timeMs=3500、depth=2、beamWidth=6、topK=3、AI seed=1729。
- 四组场景：A 面无自然之灵 seed=11；B 面无自然之灵 seed=13；A 面有自然之灵 seed=17；B 面有自然之灵 seed=19。
- 每组运行两场双人直接对局，同一初始种子，交换 v1/v2 所在座位和先后手，共 8 场。总分相同按实际规则比较已入住动物方块数，仍相同记平局。
- 每组另让 v1、v2 分别运行同一种子的 Solo，共 8 场，以实际总分配对比较。
- 总计 16 场，严格串行，避免两个 AI 同时竞争 CPU。场景之间交替先运行哪个版本，每场正式计时前各做一次 100 ms 配置的预热，预热方案丢弃，不计入统计。
- 每次 `searchTurn` 从调用到返回用外部时钟测量，包括其保底、搜索及日志准备；另记进程 CPU 时间、内部报告耗时、完成深度、保底标志及完整动作序列。模型导入、预热、真实动作执行与 UI 展示不计入思考时间。

这里的“相同时间”准确指相同的 3.5 秒**可用软预算**，不是强迫双方恰好消耗相同 CPU 毫秒。两版都必须完成当前回合保底，已开始的计算也可能越过截止时间，因此同时报告实际耗时和超限幅度。旧版保留原本 65% 搜索 / 35% 日志的分配，不额外赠送搜索时间。算法提前完成可以少用时间，不填充等待。

这是预先固定的四个种子的初测。交换座位的两场有相关性，不当成两个独立随机种子；少量场景的胜率和分差不能证明一般局面中的稳定优势。真实限时运行受硬件和负载影响，可复现的是实验配置与过程，不保证动作逐次完全一致。

## 运行与结果文件

```sh
npm run benchmark:compare-ai
```

默认每场结束后更新 `/tmp/harmonies-ai-time-comparison.json`，包含配置、旧提交、新版源码 SHA-256、Node/CPU 信息、每回合计时/动作、计分明细与汇总。

可用环境变量：

- `AI_COMPARE_MS`：双方每回合相同思考预算，默认 3500。
- `AI_COMPARE_OUTPUT`：结果路径。
- `AI_COMPARE_REF`：旧版参考 Git 提交，默认 f36c7cc。
- `AI_COMPARE_LIMIT`：只运行排定列表前 N 场，供快速检查；不完整配对的结果不用于配对强度结论。

脚本验证：100 ms、1 场完整双人局的冒烟运行通过；单独 TypeScript 检查通过。100 ms 冒烟运行不作为强度实验结果。

## 本批实测结果

2026-09-28（America/Los_Angeles）运行，共 16 场、256 个玩家行动回合。运行环境、源码摘要及 UTC 起止时间保存在原始 JSON。全部对局正常结束，所有动作、资源守恒、新旧计分等价与多人等回合数检查通过。

### 双人直接对局

表内比分统一为 **v2 : v1**；分差为 v2 减 v1。

| 场景 | 种子 | v2 先手 | v2 后手 | 两场平均分差 |
| --- | ---: | ---: | ---: | ---: |
| A，无自然之灵 | 11 | 51 : 96 | 83 : 86 | −24 |
| B，无自然之灵 | 13 | 125 : 137 | 129 : 158 | −20.5 |
| A，有自然之灵 | 17 | 108 : 81 | 87 : 98 | +8 |
| B，有自然之灵 | 19 | 136 : 115 | 114 : 147 | −6 |

合计 v2 2 胜、6 负、0 平；平均分差 −10.625。无自然之灵的两组种子均落后；A 面有自然之灵的配对平均占优；B 面有自然之灵的配对平均落后。不能将单个场景的结果推广到该模式的所有种子。

### 实际耗时与搜索覆盖

以下包含全部双人局与 Solo 行动回合。双方设定预算均为 3500 ms。

| 指标 | v1 | v2 |
| --- | ---: | ---: |
| 玩家行动回合数 | 129 | 127 |
| 实际平均思考耗时 | 2387 ms | 2735 ms |
| 实际耗时 P95 | 3942 ms | 3513 ms |
| 实际最长思考耗时 | 4437 ms | 3913 ms |
| 进程平均 CPU 时间 | 2692 ms | 3255 ms |
| 超过预算 100 ms 以上的回合 | 19 | 2 |
| 仅贪心保底回合 | 2 / 129（1.6%） | 60 / 127（47.2%） |
| 日志所记完成深度 0 / 1 / 2 | 2 / 75 / 52 | 60 / 27 / 40 |

CPU 时间为进程各线程之和，可因 V8 并行 GC 等工作高于墙钟耗时。较少的真实回合数来自不同 Solo 策略的终局时机；每场双人对局内部，两位玩家回合数均相等。

旧版有更明显的软预算超限，新版也不是硬截止。因此本批是**相同可用预算**的比较，不是实际计算时间逐回合严格相等的比较。虽然新版平均墙钟与 CPU 用时均更多，不能据此消除旧版在具体关键回合超时带来的影响；严格硬预算实验需要另行规定两版共同的中断与可提交方案协议。

新版的完整 V 估值和全量候选展开伴随着更高保底比例；这说明默认预算下搜索覆盖受到了影响，但本实验同时改变了估值、预算公式、规范朝向、剪枝与缓存实现，不能只凭相关性把全部分差归因于保底。旧版便宜预筛选也可能有策略偏好上的优势。要确定原因，需要分别固定搜索策略或估值函数的消融实验。

因此，当前能确认的是：已修复估值/日志一致性问题，但**不能把 v2 称为已经验证更强的 AI**。本批终局成绩给出了需要继续优化的回退信号；未根据这些成绩临时调参或修改 AI。
